# Skill 生命周期治理升级

日期：2026-11-09（北京时间）

## 设计依据与范围

完整调研见 [主流管理思路对比](skill-management-research-2026-11-09.md)。采用 Agent Skills 格式、中央库分发、显式作用域、期望与实际状态分离、内容基线校验的组合。保留 React 19 / Tauri 2 / Rust 和已有 Forklift，不增加第二套数据库或替换现有分配方式。

升级将现有安装、收藏、预设、全局/项目分配、上游更新、Git 快照恢复串联到新增的治理检查入口。新增核心由桌面和 CLI 共用；直接扫描实际文件，不以数据库显示的“已同步”代替内容校验。Forklift 的 context 仍只管理它自己的 Codex 分配，桌面的多工具分配仍由原有模型管理，不相互隐式覆盖。

## 新增使用流程

1. 从侧栏打开“技能治理”，查看格式、来源、重复内容、长文档和基线差异。
2. 处理标为“需修复”的问题。兼容文件名、目录名不一致和部分工具扩展字段会提示兼容性问题，不自动改写内容。
3. 创建基线前查看新增、变化、移除、保持数量，确认后保存。确认期间内容或旧基线发生变化会拒绝写入，要求重新扫描。
4. 安装、更新或人工编辑 Skill 后，刷新扫描查看差异。需要查看上游差异时使用技能库现有更新功能；确认需要接受这些变化后再更新基线。
5. 需要恢复旧内容时使用原有 Git 版本历史恢复，再校验基线。将基线文件与技能内容一起纳入 Git 备份，可验证取出的快照是否匹配。

基线不是远程安装清单，不会联网下载或恢复文件；浮动分支不会被宣称为固定 commit。来源从现有 `.skills-manager/skills/*.json` 读取并脱敏；缺少来源和固定修订时如实显示未知。格式检查和内容一致不代表技能执行效果或安全性已经验证。

## 命令行与自动化检查

```powershell
# 只读检查当前中央库
npm run -s cli -- --json governance inspect

# 针对项目内实际 Skill 实体目录，不初始化数据库
npm run -s cli -- --skills-root E:/example/.agents/skills --json governance inspect

# 确认当前内容为基线，不改写技能内容
npm run -s cli -- --skills-root E:/example/.agents/skills --json governance lock --yes

# 用于 CI：内容新增、变化、缺失、无法读取、基线缺失或格式错误均退出 1
npm run -s cli -- --skills-root E:/example/.agents/skills --json governance verify
```

`inspect` 有错误时也返回非零，但未建立基线和正常的内容变化只作为检查结果。`verify` 除错误外还要求存在基线且所有技能一致。正常报告输出到 stdout，运行失败原因输出到 stderr。`lock` 缺少 `--yes` 时拒绝写入；未知或损坏的已有锁文件不会被静默覆盖。

## 文件契约

- 独立文件名 `skills-manager.lock.json`，不覆盖生态已有 `skills-lock.json`。这是本项目格式，不宣称与 Vercel 或 Agent Skills 的锁文件标准兼容。
- 格式版本 `schema_version: 1`，摘要算法 `sha256-framed-v1`；按相对路径排序，文件路径和字节长度分帧，计算 SHA-256。
- 锁定 Skill 的受检查文件内容，包括正文、脚本、引用和资源；排除 `.git`、`node_modules`、Python 缓存、系统垃圾文件及管理器内部元数据。不能用于证明被排除的运行依赖没有变化。
- 忽略时间戳，不记录本机绝对目录作为技能身份；路径采用 `/` 分隔，便于 Git 迁移。
- 不跟随 Skill 内符号链接/Junction，不执行脚本。读取失败不能被吞掉后误判“一致”。库根可解析为实际位置，库内链接需先检查归属。
- 排他锁和同目录临时文件原子替换保护写入；已有锁文件为链接或硬链接时拒绝覆盖。`.skills-manager-governance.guard` 仅作本机并发控制，不纳入技能 Git 备份。
- “与基线一致”只代表受检查的文件字节一致，不是恶意内容检测或可信来源认证。

## 验收要求

| 要求 | 证据 |
| --- | --- |
| 最新方案调研与取舍可追溯 | 调研归档中的一手来源和快照口径 |
| 实际文件、格式和差异可见 | Rust 核心测试与隔离 CLI 场景 |
| 基线新增/变化/缺失/坏格式可检测 | 锁定、编辑、校验的端到端结果 |
| 确认状态不可静默过期 | 预览元组比对和双扫描测试 |
| 桌面与 CLI 使用同一核心 | Tauri 命令注册、CLI 路由、前端构建 |
| 桌面加载、筛选、确认、异常可用 | 桌面宽度浏览器验证；浏览器桥接使用隔离样例，真实逻辑另由 Rust/CLI 验证 |
| 原有未提交修改保留 | 仅提交本次新增文件及专属差异 |
